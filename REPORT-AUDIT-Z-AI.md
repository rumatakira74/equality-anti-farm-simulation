## Находки

### 🟠 AUDIT-Z-EQ-01. `python farm_model.py --group` без флага группы — молча не делает ничего

**Файлы:** `README.md:25` (и `README-ENG.md:26`) против
`Mistral/farm_model.py:1383-1407` (`main()`).

**Описание:** README подаёт `--group` как самостоятельный режим
(«группировка прогонов»), но в `main()` флаг действует только в связке с
`--stage12`/`--block3`/`--a9`; без них команда завершается без результата
и без предупреждения. Пользователь, следуя README, получает «ничего не
произошло» без диагностики.

**Воспроизведение:** `python3 -I Mistral/farm_model.py --group` → нет
вывода/файлов.

**Предложение:** поправить README (`--stage12 --group …`) и/или добавить
в `main()` явную ошибку «--group требует --stage12|--block3|--a9».

### 🟠 AUDIT-Z-EQ-02. Снимки документов в сим-репо устарели на одну итерацию правок tnp

**Файлы:** `KNOWLEDGE.md` (снимок v9.3 от 19.10.2026: раздел 7.7 со
старыми числами — пик ~40% на m27, пересечение «на 38-м месяце»,
`KNOWLEDGE.md:366-371`) против актуального tnp `docs/KNOWLEDGE-3.md:113,128`
(v9.16: пик 38,6% m28, пересечение 54-й месяц при $200 / 39-й при $120);
`farm-attack-economics.md` — копия без ERRATUM, тогда как в tnp
(`docs/farm-attack-economics.md:3-9`) ERRATUM от 04.11.2026 внесён.

**Описание:** читатель сим-репо получает цифры, которые платформа
официально признала устаревшими (см. ERRATUM), без ссылки на устаревание.
Для репозитория, на который ссылается спека как источник обоснования
параметров, это риск рассинхронизации «модель ↔ документ».

**Предложение:** либо обновлять снимки при каждой правке исходников
(скрипт синхронизации + проверка в CI сим-репо), либо заменить снимки
короткой ссылкой на tnp-версию с пометкой «источник истины».

### 🟡 AUDIT-Z-EQ-03. `unittest.main()` стоит до шести тестовых классов

**Файл:** `Mistral/test_farm_model.py:226-227` — `unittest.main()` перед
`TestBlock4Recurring` и всеми A9-классами (строки 230-493).

**Описание:** при документированном запуске
`python3 -m unittest discover -s Mistral` все 41 тест находятся и
проходят (проверено: `Ran 41 tests … OK`), но прямой запуск
`python3 Mistral/test_farm_model.py` исполняет только первые 16 тестов и
выходит из `unittest.main()` — поздние классы даже не определяются.
Тихое частичное покрытие для тех, кто запустит не по документированной
команде.

**Предложение:** перенести `unittest.main()` в конец файла.

### 🟡 AUDIT-Z-EQ-04. README утверждает 49 CSV этапа 1.2, фактически 47

**Файлы:** `README.md:10` и `README-ENG.md:11` («results/ — 49 CSV
свипов + stage12_summary.csv») против фактического содержимого
`Mistral/results/` и `git ls-tree -r main` — 47 CSV `s12_*` + summary.

**Описание:** счёт в README не совпадает с репозиторием; удалений s12_*
в истории нет — вероятно, счёт занижен при добавлении/переименовании
сценариев. Дезориентирует при сверке «документ ↔ артефакты».

**Предложение:** поправить счёт в обоих README.

### 🟡 AUDIT-Z-EQ-05. Жёсткие индексы m60/m38 без проверки длины прогона

**Файлы:** `Mistral/farm_model.py:912-915, 1075-1076, 1204-1205, 1307`
(`mean_rows[59]`, `r[59]`, `mean_rows[37]`).

**Описание:** при пользовательском сценарии с `months < 60` будет
IndexError без диагностики; при `months` в диапазоне 38-59 — частично
некорректные метрики (payback/crossing молча берутся по доступным
индексам или падают). Для исследовательской утилиты, где месяцы —
параметр, это хрупко.

**Предложение:** валидация `months >= 60` для сценариев, использующих
метрики m60/m38, либо вычисление индексов от длины.

### 🟡 AUDIT-Z-EQ-06. Прогон без numpy даёт другой вывод при тех же seed

**Файлы:** `Mistral/farm_model.py:375-377` (`rng.poisson`) против
фолбэка `Mistral/farm_model.py:247-270` (`_poisson_fallback`).

**Описание:** траектории Пуассона различаются между numpy-путём и
фолбэком, поэтому те же seed без numpy дают другие байты CSV — сверка по
`a9_manifest.sha256` «громко» падает без объяснения причины (наличие
numpy проверяет только README, не `reproduce_a9.sh`). Детерминизм в
каждой из сред есть (проверено: два прохода с numpy байт-идентичны и
совпадают с манифестом 15/15), но переносимость манифеста между средами
не обеспечена.

**Предложение:** `reproduce_a9.sh` проверяет наличие numpy с внятной
ошибкой; или зафиксировать в манифесте среду (numpy version).

### 🟡 AUDIT-Z-EQ-07. Унаследованные находки A9 подтверждены и остаются открытыми

  а не заменяет его (`farm_model.py:603` против комментария `:198`;
  AUDIT-A9-04, эффект ~1%);
- дефолт `device_cost = 120` при публичном значении $200

  обоснование «канарейка пинует» признано неверным (AUDIT-A9-02).

**Предложение:** закрыть три пункта решениями владельца (код или
документация), чтобы blind-аудитам не приходилось их переоткрывать.
