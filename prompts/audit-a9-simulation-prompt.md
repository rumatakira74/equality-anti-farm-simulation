# Тема Blind-аудит ветки a9-simulation (тема A9 — пересчёт анти-фарм-симуляции) — ветка audit-a9-simulation (только чтение и reports/)

**Предусловие:** ветка `a9-simulation` запушена в репо eq (tip `ece779d`; если tip ушёл — работать по текущему tip, сверив предусловия, при сомнении — стоп-вопрос). Запуск — по команде владельца (дана). Ветка `audit-a9-simulation` — **от текущего tip ветки `a9-simulation`** (не от main: аудит должен видеть работу темы). **Режим: только чтение и `reports/` — код модели, тесты, спека, README, промпты НЕ трогать; находки не править (правки — отдельное решение владельца).** Репо tnp (equality-trust-networks) — **только чтение** (источник фактов). Основание: схема контроля качества (исполнитель → blind-аудит → merge по подтверждению владельца после дайджеста). CI в репо eq не настроен — правило CI-verify не применимо, факт отсутствия CI отметить в отчёте. Живых сетей нет.

**Слепость:** аудит независимый. Пункты 1–5 выполняются ДО открытия отчёта исполнителя `reports/REPORT-A9-SIMULATION.md`; его заявления — не истина, а гипотеза для сверки в пункте 6.

**Цель:** механически проверить полноту и качество исполнения мандата `prompts/a9-simulation-prompt.md` (eq main) по факту кода, тестов и воспроизводимых прогонов; выдать вердикт готовности ветки к merge.

**Пункты:**

1. **Полнота мандата.** По каждой задаче мандата — статус по факту с доказательством (файл/строка/коммит): (1) инвентаризация фактов из кода tnp main — только чтение, сверить ключевые значения по коду tnp: TargetLight/TargetHard, Argon2id (объём/итерации/параллелизм), механика окна челленджа mint (±48 ч, слот от хеша addr‖period, M4, accrual_window), привязка SPKI листа аттестации (фикс A1), RepeatAndroidIDTarget; (2) модель «кошельков на устройство» (параметры, издержки обхода, $200/README + чувствительность $120/$300); (3) стоимость PoW из фактических таргетов (замеры, электричество, выигрыш железа GPU/ASIC); (4) окно mint параметром в двух вариантах (после фикса A — 0 % потерь; как в коде — достижимость 1/15, поглощение (14/15)^6, автоматизация фермы); (5) прогоны по сценариям 7.7 + канарейка регрессии 1.1 (RNG и поведение базовой модели не тронуты); (6) скрипты воспроизведения + манифесты SHA-256; (7) отчёт `reports/REPORT-A9-SIMULATION.md`.

2. **Независимость базовой модели (критично).** Канарейка 1.1: прогнать `--regression` до/after-логику самостоятельно и сверить с заявленными числами (236/31/11,5 %, 577/306/34,3 %, 8481/1140/12,0 %); RNG-профиль базовой модели 1.1 не изменён (`git diff main...a9-simulation -- Mistral/farm_model.py`: новые параметры дефолтно выключены, пути базовых сценариев не затронуты). Канарейка должна проходить на чистом дереве темы.

3. **Воспроизводимость прогонов.** `./Mistral/reproduce_a9.sh --seed 1` (и минимум один дополнительный seed) — сверка CSV с манифестами SHA-256 байт-в-байт; хотя бы один сценарий — полным независимым пересчётом метрик из CSV (доля фермы m60, пик, безубыточная цена, месяц пересечения $0,01). Прогоны — по одному за раз.

4. **Тесты.** `python3 -m unittest discover -s Mistral -p "test_*.py"` — все зелёные (заявлено 41); новые 17 тестов покрывают параметры A9 (таргеты, PoW-стоимость, GPU/ASIC, кошельки/устройство, окно mint, сценарии, окупаемость). Упавший тест — блокер вердикта.

5. **Процесс и гигиена ветки.** `git diff main...a9-simulation` — только предмет темы (модель A9, тесты, скрипт воспроизведения, results/ манифесты и CSV, отчёт, FINDING-файлы, .gitignore). Правки вне мандата (базовая 1.1, block4, спека, доки tnp) — FINDING «вне мандата». Файлов больше 1 МБ нет (артефакты темы должны были уйти в R2 — заявлено, что не потребовалось: проверить размеры); секретов и ключей нигде нет; `git status` чист.

6. **Сверка с отчётом исполнителя.** Только теперь открыть `reports/REPORT-A9-SIMULATION.md`: каждое ключевое заявление (факты tnp с file:line, параметры модели, результаты 14 сценариев, канарейка, PoW-замеры, выводы по окну mint и кошелькам/устройству, PENDING/FINDING) — подтверждено кодом/коммитом/собственным прогоном или расходится (цитата + факт). Расхождения — в таблицу.

7. **FINDING вне мандата.** FINDING-A9-01 (pow-host.md в tnp занижает итерации усиленного PoW) и FINDING-A9-02 (block4 игнорирует --out) — проверить по коду, подтвердить или опровергнуть фактом; значимость и рекомендация — в таблице находок. Крипто-безопасность протокола — отдельный контур, глубоко не исследовать.

**Ресурсные правила (обязательно):** тяжёлых параллельных прогонов не запускать; прогоны симуляции — по одному за раз; стоп при <2 ГБ свободной памяти или тормозах машины → FINDING + стоп-вопрос; после прогонов оставшихся процессов не оставлять.
